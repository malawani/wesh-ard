# ترحيل المفضلة

الإصدار: schemaVersion 2. المفتاح الجديد wesh-ard:v2:favorites.

المصدر الفعلي wesh-ard:favorites:v1. تقرأ أداة الترحيل أيضًا المفاتيح التاريخية المحتملة المذكورة في المواصفات، دون الادعاء أن المستخدم استخدمها.

يحتفظ كل رد قديم بمعرّفه الأصلي في id وlegacyId، بما في ذلك 36 نسخة بحسب المرحلة. لا نغير نص المفضلة أثناء المطابقة. إذا تعارض النص والمعرّف، نبحث عن النص نفسه؛ وإن لم نجد نحفظه كما هو في عنصر orphaned دون ربطه بموقف خاطئ.

يُدمج المصدر ويزال تكراره، ثم تكتب حاوية V2 وتقرأ للتحقق من نجاح الكتابة. لا تزال المصادر القديمة محفوظة. بعد النقل الناجح تجعل migratedLegacy: true بيانات V2 مرجعًا، فلا تعود العبارات المحذوفة من المفضلة عند التحديث. فشل القراءة أو وجود إصدار مستقبلي أو بيانات V2 تالفة يمنع الكتابة فوقها. واجهة التطبيق توضح الحفظ المؤقت للجلسة عند الفشل.

التحقق يرفض نصوصًا فارغة ويهمل الخصائص غير المعروفة. الحدود الوقائية: 2 مليون وحدة نصية و5000 عنصر لكل مصدر، و4000 وحدة للعبارة المستوردة. تجاوز حجم المصدر يمنع إعلان نجاح النقل ولا يحذف المصدر.

خريطة المرحلة القديمة: early → getting_to_know، mutual → mutual_crush، love → love، serious → legacy_serious. لا تخمين بين engaged وmarried. هذا مساعد ترحيل اختُبر؛ لم تكن هناك إعدادات مرحلة محفوظة أصلًا لنزعم نقلها.

## الرجوع

- النسخة الأصلية محفوظة في Git والـZIP الأصلي مستقل.
- الرجوع للكود القديم لا يمس مفاتيح المتصفح الجديدة أو القديمة، لكنه يقرأ المصدر القديم فقط ولا يرى ما أضيف حصريًا في V2.
- لا توجد آلية رجوع تزعم مزامنة التغييرات الجديدة مع V1. احتفظ ببيانات المتصفح قبل أي رجوع تجريبي.
- نقل الملفات إلى موقع جديد لا ينقل بيانات localStorage للمستخدم. يلزم تصميم تصدير واستيراد مدقق قبل دعم هذه الحالة؛ لم يُنفذ هنا.
