5M. MANIFEST ACCEPTANCE
----------------------------------------

اكتب Validator يتحقق من:

- عدد canonical IDs = 320.
- عدد المسارات = 12.
- أعداد المواقف حسب كل مسار مطابقة.
- المعرفات فريدة.
- أسماء المواقف غير فارغة.
- لا توجد تكرارات معنوية واضحة.
- 30 معرفًا قديمًا محفوظًا.
- جميع المواقف الجديدة مكتملة المحتوى.
- لا يحتسب alias على أنه موقف جديد.
- لا يحتسب ربط موقف بمسار إضافي مرتين.

المواقف القريبة معنويًا بين المسارات
يجب أن يكون لها غرض مختلف موثق.

مثلًا:
«الرد على اشتقت لك» يختلف عن
«إنشاء رسالة شوق» من حيث اتجاه الرسالة.

لكن لا تنشئ نسختين من نفس الموقف
بالاسم والسلوك والعبارات فقط لزيادة العدد.

==================================================
9. CONTENT DATA MODEL
==================================================

استخدم نموذج بيانات منظمًا يشبه التالي.

يمكنك تعديله هندسيًا مع الحفاظ
على جميع الخصائص الأساسية.

type RouteId =
  | "reply"
  | "send"
  | "guide"
  | "open"
  | "continue"
  | "flirt"
  | "confession"
  | "reconcile"
  | "care"
  | "occasions"
  | "meeting"
  | "quick";

type ToneId =
  | "casual"
  | "romantic"
  | "tender"
  | "confident"
  | "bold_respectful"
  | "deep"
  | "poetic"
  | "playful"
  | "mature"
  | "supportive"
  | "clear"
  | "subtle";

type MessageLength =
  | "short"
  | "medium"
  | "long";

type Intensity = 1 | 2 | 3;

interface ResponseContent {
  id: string;
  text: string;
  tones: ToneId[];
  allowedStages: string[];
  intensity: Intensity;
  length: MessageLength;
  dialect: "sa";
  tags: string[];
  legacyId?: string;
}

interface SituationContent {
  id: string;
  canonicalRoute: RouteId;
  relatedRoutes?: RouteId[];
  title: string;
  description: string;
  intent: string;
  trigger: string;
  keywords: string[];
  contextQuestions?: ContextQuestion[];
  advice: string;
  avoid: string[];
  sensitivity:
    | "normal"
    | "careful"
    | "boundary_sensitive";
  replies: ResponseContent[];
}

interface ContextQuestion {
  id: string;
  title: string;
  choices: {
    value: string;
    label: string;
  }[];
  optional: boolean;
}

ملاحظات:
- allowedStages مؤثر فعليًا.
- tones يسمح بأكثر من وصف للجملة عند الحاجة.
- id لكل عبارة ثابت.
- النصوص الموجهة للمؤنث لا تحول آليًا
  إلى مذكر باستبدال حرف أو لاحقة فقط.
- إمكانية مخاطبة المذكر أو المؤنث
  تضاف عند توفر محتوى مدقق لكل صيغة.
- لا تعرض خيارًا لم تنفذ دعمه فعليًا.

==================================================
10. QUALITY STANDARD FOR 2560 RESPONSES
==================================================

كل موقف يحتوي 8 عبارات فعلية على الأقل.

يجب أن تكون العبارات:
- سعودية طبيعية.
- سهلة القراءة والنسخ.
- صادقة وغير متكلفة.
- مرتبطة بالموقف.
- متنوعة في الأسلوب.
- مناسبة لمرحلة العلاقة.
- متباينة في الصياغة والمعنى أو
  زاوية التعبير.
- محترمة للطرف الآخر.

لا تكتب ثماني نسخ من جملة واحدة.

مثال سيئ:

أنتِ جميلة.
أنتِ جميلة جدًا.
أنتِ جميلة مرة.
أنتِ جميلة بشكل كبير.

هذه ليست أربع عبارات متنوعة مفيدة.

بدل ذلك نوّع بين:
- مدح تفصيل محدد.
- مدح شخصية.
- تلميح مرح.
- تعبير عفوي.
- تعبير ناضج.
- رد قصير.
- رد متوسط.
- تعبير أعمق عندما يناسب.

لا تفرض تغطية 12 نبرة داخل كل موقف؛
يكفي وجود نبرات مناسبة وسياقية.

يجب أن تكون النبرات الاثنتا عشرة
موجودة فعلًا في المكتبة الشاملة،
ولكل نبرة محتوى كافٍ لتكون مفيدة.

ضع حدًا أدنى مستهدفًا للتغطية
على مستوى المكتبة، مع استثناءات
معللة للمواقف الحساسة.

لا تستخدم API لتوليد الردود عند
وقت زيارة المستخدم في هذه المرحلة.

يمكنك استخدام أدوات التأليف أثناء
التطوير لكتابة المحتوى، لكن يجب
حفظ النصوص النهائية في ملفات فعلية
ومراجعتها والتحقق منها.

11. CONTENT VALIDATION
==================================================

أنشئ سكربت:

scripts/validate-content.ts

وأمر تشغيل:
npm run validate:content

يتحقق من:

1. إجمالي المواقف = 320.
2. عدد المواقف لكل مسار.
3. عدد الردود >= 2560.
4. كل موقف لديه >= 8 ردود.
5. جميع معرفات المواقف فريدة.
6. جميع معرفات الردود فريدة.
7. لا توجد نصوص فارغة.
8. لا توجد placeholders.
9. لا توجد معرفات يتيمة.
10. allowedStages صالحة.
11. tones صالحة.
12. intensity بين 1 و3.
13. length صالح ومتوافق مع النص.
14. جميع النبرات الـ12 مستخدمة.
15. المواقف الحساسة لديها advice وavoid.
16. المواقف التي تتطلب احترام الرفض
    لا تقترح الإلحاح أو تجاوز الحدود.
17. لا توجد نسخ متطابقة بعد تطبيع
    الحروف والمسافات والتشكيل.
18. افحص التشابه العالي بين الجمل،
    واعرض الحالات المشتبه بها للمراجعة.
19. جميع العبارات القديمة الست لكل
    موقف قديم ما زالت محفوظة.
20. معرفات الجمل القديمة محفوظة
    أو لها خريطة ترحيل موثقة.

reports/content-validation.json

بالإضافة إلى تقرير مقروء:

reports/content-validation.md

إذا لم تكتمل الشروط، لا تعلن
أن المكتبة وصلت إلى هدفها.

==================================================
12. DATA MIGRATION AND BACKWARD COMPATIBILITY
==================================================

هذه من أهم مراحل التنفيذ.

ممنوع فقدان المفضلة القديمة
بسبب تغيير معرفات الردود.

المشروع السابق قد يحتوي على:

localStorage keys:
wesh-ard-favorites-v1
wesh_favs_v02
wesh-ard-repaired-favorites-v03

افحص المستودع الفعلي قبل تحديد
الصيغ النهائية.

قد تختلف أشكال عناصر المفضلة القديمة.

أمثلة:
{
  id: "miss:soft:0",
  sceneId: "miss",
  title: "قالت: اشتقت لك",
  text: "وأنا والله فقدت سوالفك."
}

أو:
{
  id: "miss|وأنا والله فقدت سوالفك.",
  text: "...",
  context: "..."
}

أو صيغ أخرى حسب الإصدار الموجود.

المطلوب:

A. PRESERVE LEGACY IDs

احتفظ بمعرفات المواقف القديمة الثلاثين:

reply:
miss, photo, crush, love, why,
voice, bored, cold, upset, night

send:
morning, chat, flirt, hint,
confess, missing, meet, support,
thanks, sorry

guide:
misunderstand, space, fading,
jealous, stress, reject, first,
busy, bounds, again

لا تستبدل هذه المعرفات
بـ reply-001 وما شابهها.

B. PRESERVE LEGACY RESPONSE IDS

في الإصدار السابق قد تكون صيغة معرف
العبارة:

<situationId>:<tone>:<index>

احتفظ بهذه المعرفات ضمن legacyId
أو أنشئ جدول تحويل ثابت إلى
معرف العبارة الجديد.

مثال:
miss:soft:0
=> miss:r001

لا تغيّر نص العبارة القديمة عند الترحيل
دون خطة واضحة لمطابقة المفضلة.

C. MIGRATION VERSION

أنشئ نظام ترحيل مرقم:

schemaVersion: 2

يجب أن يكون:
- قابلًا لإعادة التشغيل بأمان.
- لا يكرر البيانات.
- لا يمسح نسخة المصدر.
- متحملًا للبيانات غير الصالحة.
- متحملًا لمنع localStorage.

D. NEW STORAGE KEY

اقترح:

wesh-ard:v2:favorites

اقرأ الصيغ القديمة.
ادمج العناصر الصالحة.
أزل التكرار عبر معرف ثابت.

اكتب البيانات الجديدة.
تحقق من نجاح الكتابة إن أمكن.

لا تحذف المفاتيح القديمة تلقائيًا.
لا تعلن نجاح النقل عند فشل التخزين.

E. UNMATCHED LEGACY FAVORITES

إذا تعذر ربط عبارة قديمة بمعرف جديد:
احتفظ بنصها الأصلي ضمن عنصر
legacy/orphaned قابل للنسخ والحذف.

لا تفقد العبارة لمجرد أن معرفها تغيّر.

F. RELATIONSHIP STAGE MIGRATION

المراحل القديمة:
