## الأعداد والمعرّفات

الأعداد مستخرجة باستخدام scripts/audit-baseline.ts من نسخة الكود المحفوظة:

- 30 موقفًا؛ 10 في كل من reply وsend وguide.
- 180 عبارة أساسية، ست عبارات لكل موقف.
- 216 معرّف نتيجة مختلفًا عند جمع المراحل الأربع القديمة: 180 عبارة أساسية و36 صيغة إضافية للمراحل.
- كل المعرّفات والنصوص موجودة في content/legacy/baseline.json.
- الصيغة القديمة للنتيجة: situation:tone:index، وللنسخ المخصصة: situation:tone:index:stage.
- مفتاح المفضلة الموجود فعلًا: wesh-ard:favorites:v1.
- المفاتيح الثلاثة الأخرى في وثيقة التوسعة احتمالات تاريخية وليست مثبتة في هذا الكود.
- لم يكن التطبيق يحفظ مرحلة العلاقة أو نص البحث في localStorage.

## الفحوص قبل التعديل

- npm ci: نجح بعد تحديد ذاكرة npm داخل مساحة العمل. المحاولة الأولى فشلت بسبب عدم إتاحة مسار الذاكرة الافتراضي؛ لم نغير ملف القفل لمعالجة ذلك.
- npm test: 26/26 ناجحة.
- npm run typecheck: ناجح.
- npm run build: ناجح، والصفحات / و/about و/privacy و404 ثابتة.
- لم يوجد مستودع Git داخل الأرشيف؛ أنشئ مستودع محلي وحفظت النسخة الأصلية قبل تعديل ملفات التطبيق.

## مخاطر الترحيل

1. تجاهل 36 صيغة مرحلة قد يفقد الربط بمفضلة صحيحة؛ لذلك حفظت جميع معرّفات التشغيل ونصوصها.
2. serious القديمة تجمع الخطوبة والزواج؛ لا يمكن استنتاج أحدهما من الآخر.
3. حذف المفتاح القديم أو تغيير عنوان الاستضافة قد يجعل المفضلة غير متاحة؛ لا حذف للمصدر ولا مزامنة بين عناوين المواقع.
4. إعادة دمج المصدر في كل تحميل تعيد المحذوفات؛ الإصدار الجديد يحفظ علامة اكتمال النقل ويعامل V2 مصدرًا بعد نجاحه.
5. البيانات غير المطابقة تحتفظ بالنص كعبارة قديمة قابلة للنسخ والحذف.
6. منع التخزين أو امتلاؤه يجب ألا يُعرض كنجاح حفظ.
7. تشابه أصلي مرتفع بين miss:direct:0 وmissing:direct:0؛ اختلاف الاتجاه موثق (رد على شوق وارد/مبادرة برسالة شوق)، والنصان محفوظان للتوافق.
8. بعض الاعتذارات الأصلية مشروطة. لم تُحذف حفاظًا على النصوص؛ تحتاج مراجعة تحريرية قبل إصدار V2 الكامل، مع تفضيل العبارات الجديدة التي تتحمل المسؤولية.
